# Color System Architecture

## Overview

The component library uses a two-tier color system:

1. **Primitive Colors**: Base color values (e.g., `light/primary/500`, `dark/slate/600`)
2. **Semantic Colors**: Application-level tokens that reference primitives (e.g., `background-brand-default`, `text-positive-default`)

## How Colors Work in Figma vs. Code

### In Figma

- Semantic colors **reference** primitive colors using Figma's variable system
- When you change a primitive color in Figma, all semantic colors that reference it automatically update
- This maintains consistency across your design system

### In Our Code

- When extracted via MCP tools, semantic colors come as **resolved hex values**
- The relationships are preserved (103 of 110 semantic colors reference primitives)
- However, they are stored as independent values in the code

## What This Means

### ✅ In Figma
- Change `light/primary/default` → All semantic colors using it update automatically

### ⚠️ In Code
- Change a primitive color → Semantic colors **do NOT** update automatically
- You need to **re-extract** semantic colors from Figma to get updated values

## Workflow for Updating Colors

### Scenario 1: Primitive Color Changed in Figma

1. **In Figma**: Update the primitive color (e.g., `light/primary/default`)
2. **Extract primitives**: Use MCP `get_variable_defs` on node `3278-5847`
3. **Extract semantic colors**: Use MCP `get_variable_defs` on node `3278-7910` (important!)
4. **Regenerate tokens**: Run `npm run generate-tokens`
5. **Validate**: Run `npm run validate`

### Scenario 2: Only Semantic Color Changed

1. **In Figma**: Update the semantic color mapping
2. **Extract semantic colors**: Use MCP `get_variable_defs` on node `3278-7910`
3. **Regenerate tokens**: Run `npm run generate-tokens`

## Analyzing Relationships

To see which semantic colors reference which primitives:

```bash
node scripts/analyze-color-relationships.js
```

This generates `figma-raw/color-relationships.json` showing:
- Which semantic colors map to which primitives
- Which semantic colors are independent (don't reference primitives)

## Example Relationships

From the analysis:
- `Theme/Primary` → `light/neutral/800` = `#2b2b2b`
- `var(--sds-color-background-brand-default)` → `light/secondary/default` = `#0a76db`
- `var(--sds-color-text-positive-default)` → `light/dayglow/700` = `#5fae52`

## Best Practices

1. **Always re-extract both** when primitives change:
   - Primitive colors (node `3278-5847`)
   - Semantic colors (node `3278-7910`)

2. **Run analysis** after extraction to verify relationships:
   ```bash
   node scripts/analyze-color-relationships.js
   ```

3. **Document changes**: When updating colors, note which primitives changed and why

4. **Test in Figma first**: Make changes in Figma, verify they work, then extract

## Future Improvements

Potential enhancements:
- Create a mapping system that preserves references in code
- Generate TypeScript types that show relationships
- Add validation that checks if semantic colors still match their primitives
- Create a sync script that automatically re-extracts semantic colors when primitives change

## Current Limitations

- Semantic colors are stored as resolved values, not references
- Manual re-extraction required when primitives change
- No automatic validation that semantic colors match their primitives
